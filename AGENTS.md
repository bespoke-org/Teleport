# Agent rules for Teleport

## Commits

Before every commit, search the GitHub issues (`gh issue list --search ...`) for ones the change
resolves, and end the message with a `Closes #N` trailer for each of them. GitHub closes the issue
when the commit reaches `main`. An issue the commit only partly addresses is mentioned in the body
instead.

## Releases

A release is a `vX.Y.Z` tag plus a CHANGELOG.md section generated by git-cliff (`just
prepare-release X.Y.Z`), committed before the tag.

- Pre-releases (`vX.Y.Z-rc.N`, GitHub release marked as pre-release) you may cut yourself, and you
  may edit their generated notes.
- A release is cut by a maintainer, or by you only after a maintainer explicitly agrees to that
  specific version in the current conversation. Up to then you prepare the changelog commit and show
  it; the tag stays uncreated and unpushed.

## Tests

Run only the `just test-one <name>` checks that cover the code you changed; `just test` builds
the app and runs every script, which is slow, and CI runs the rest. Run the full `just test` before
a release or when asked.
